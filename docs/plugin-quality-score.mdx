---
title: "Plugin Quality Score"
description: "A 0-100 score and A-F grade for a plugin's manifest, commands, agents, hooks and mods, on the same scale as the skill quality score."
---

The skill quality score grades a `SKILL.md`. The plugin quality score grades the parts a plugin adds around its skills: the manifest and its marketplace entry, commands, agents, hooks, mods (hooks modules), and the always-on context the plugin loads. It reads files only. It runs no plugin code, calls no LLM, and needs no API key.

Bundled skills keep their own skill quality score. The plugin score does not average them in; a plugin passes only when each bundled skill also passes on its own.

## Run it

```bash title="Score one plugin"
skillevaluator plugin-quality-check ./my-plugin
```

`plugin-quality-check` (also `tier1 plugin-quality-check`) exits non-zero when the plugin does not pass.

Inside `validate --type plugin`, the `quality` check runs the plugin score instead of being skipped. There it is **advisory by default**: the score, the grade and every deduction are reported, but they do not change the exit code. Add `--enforce-plugin-quality` to make the `quality` check fail when the plugin does not pass. `--checks quality` and `--skip quality` select it as before.

```bash title="Advisory in a full run, enforced on request"
skillevaluator validate ./my-plugin --type plugin
skillevaluator validate ./my-plugin --type plugin --enforce-plugin-quality
```

## Same scale as the skill score

| Dimension | Weight | What it covers for a plugin |
| --- | --- | --- |
| Correctness | 35% | Manifest validity, component paths, name, author and version, hook wiring, mod modules |
| Discoverability | 25% | Plugin description, command and agent descriptions, mod tool and command descriptions, README, hook transparency |
| Reliability | 25% | Hook script error handling, timeouts, execute bits, tests, mod tests, README limitations |
| Efficiency | 15% | Always-on context, hooks that run on every tool call, large fixed hook output, unfiltered mod handlers |

Each dimension starts at 100 and loses fixed points per rule, never going below 0. The score is the weighted sum, rounded to one decimal. Grades are A for at least 90, B for at least 80, C for at least 70, D for at least 60, and F below 60, as for skills.

A plugin **passes** when all three hold:

1. its score is at least `--min-score` (default 70);
2. no rule with severity `error` fired;
3. every bundled skill passes its own skill quality score.

Each reason a plugin does not pass is listed in `blocking`, for example `score 64.0 < 70`, `error rule: mod_module_invalid`, or `bundled skill 'x' failed quality`. In advisory mode, `error` deductions are reported as MEDIUM findings marked `would_block`; with `--enforce-plugin-quality` they are HIGH and each blocking reason fails the check.

## Rules

Points and parameters below are the packaged defaults from `plugin-quality-default.yaml`. A rule that deducts "each" deducts its points per item, up to its `cap`, as one finding. Every rule names its source: the Claude Code documentation page it follows, or the skill quality rule it mirrors.

## Plugin formats

Rules marked "all formats" apply to every manifest SkillEvaluator reads (Claude Code, Agent Plugins, Codex, Cursor, OpenClaw). Rules marked "Claude Code" cover features documented only for Claude Code plugins: hooks files, mods, and `${CLAUDE_PLUGIN_ROOT}`. For any other manifest these rules do not run, and the report lists them in `not_applicable`.

The author and version rules also read the plugin's entry in a Claude Code `marketplace.json` found at the plugin root or up to two folders above it, so a plugin that keeps its version only in the marketplace is not penalized. A missing `keywords` field is never penalized.

## Mods

A mod is a plugin whose `hooks.json` lists hooks modules under `modules` (see the [mods reference](https://code.claude.com/docs/en/plugins/mods/reference)). The score reads mods statically:

- each module path is resolved relative to the hooks file, must stay inside the plugin, and must export a named `register` function (`export function register`, `export const register`, or `export { register }`);
- `$.tool.register({...})` and `$.command.register({...})` calls in the mod's source files are cut out with a scanner that respects strings, comments and braces, and their top-level `name` and `description` are read;
- a description counts only when it is a string literal, or literals joined with `+`. A variable, a call, or a template literal with a `${}` placeholder is never scored; it is counted in `metrics.unresolved_registrations` instead;
- handlers are read from the `register(on)` parameter: `on('tool.call', { tool: 'Bash' }, hook)` is filtered, `on('tool.call', hook)` is not.

Hooks files that hold both `hooks` and `modules` are read both ways.

## Configure the rules

`--plugin-quality-config PATH` merges a YAML file over the packaged rules. List any subset of rule IDs and keys; omitted keys keep their packaged values. Lists replace the packaged list. `points: 0` turns a rule off. `dimension` and `applies_to` cannot change. An unknown rule or key, a negative point value, or an unknown severity is a usage error.

```yaml title="plugin-quality.yaml"
rules:
  readme_missing:
    points: 0
  context_cost_high:
    max_tokens: 8000
  hook_matcher_broad:
    events: [PreToolUse]
```

The report records the file name and a digest of the rules the file declares, beside `--min-score`, under `plugin_quality.config`. `--quality-config` still configures the skill score used for bundled skills.

## What the score does not cover

Security is not scored. Hook commands, MCP servers, secrets and code risk stay in the security gates (SkillSpector, Code Risk, Secrets Detection), as they do for skills.

### Future rules

- **Invalid hook matcher.** Claude Code matchers are JavaScript regular expressions; Python cannot decide all of them statically, so an invalid matcher is not scored yet.
